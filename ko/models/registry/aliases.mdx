---
title: 별칭으로 아티팩트 버전 참조하기
---

하나 이상의 별칭(alias)을 사용하여 특정 [아티팩트 버전](/ko/models/artifacts/create-a-new-artifact-version/)을 참조할 수 있습니다. 동일한 이름으로 연결하는 각 아티팩트에 대해 [W&amp;B가 자동으로 별칭을 할당](/ko/models/registry/aliases/#default-aliases)합니다. 또한 [하나 이상의 사용자 지정 별칭을 생성](/ko/models/registry/aliases/#custom-aliases)하여 특정 아티팩트 버전을 참조할 수도 있습니다.

별칭은 레지스트리 UI에서 해당 별칭 이름이 표시된 직사각형으로 나타납니다. [별칭이 보호된 상태인 경우](/ko/models/registry/aliases/#protected-aliases) 잠금 아이콘이 있는 회색 직사각형으로 표시됩니다. 그렇지 않은 경우 별칭은 주황색 직사각형으로 표시됩니다. 별칭은 레지스트리 간에 공유되지 않습니다.

<Note>
  **별칭과 태그를 각각 언제 사용해야 하는지**

  별칭은 특정 아티팩트 버전을 참조할 때 사용합니다. 하나의 컬렉션 내에서 각 별칭은 고유합니다. 동시에 특정 별칭을 가질 수 있는 아티팩트 버전은 하나뿐입니다.

  태그는 공통 주제를 기준으로 아티팩트 버전 또는 컬렉션을 구성하고 그룹화할 때 사용합니다. 여러 아티팩트 버전과 컬렉션이 동일한 태그를 공유할 수 있습니다.
</Note>

아티팩트 버전에 별칭을 추가할 때, 선택적으로 [레지스트리 자동화](/ko/models/automations/automation-events/#registry)를 실행하여 Slack 채널에 알리거나 웹훅을 트리거할 수 있습니다.

<div id="default-aliases">
  ## 기본 별칭
</div>

W&amp;B는 동일한 이름으로 연결하는 각 아티팩트 버전에 대해 자동으로 다음 별칭을 부여합니다.

* 컬렉션에 가장 최근에 연결한 아티팩트 버전에는 `latest` 별칭을 부여합니다.
* 고유한 버전 번호를 부여합니다. W&amp;B는 연결하는 각 아티팩트 버전을 0부터 시작해 개수를 셉니다. 이 개수 값을 사용해 해당 아티팩트에 고유한 버전 번호를 부여합니다.

예를 들어, `zoo_model`이라는 이름의 아티팩트를 세 번 연결하면, W&amp;B는 각각 `v0`, `v1`, `v2`라는 세 개의 별칭을 생성합니다. 이 중 `v2`에는 `latest` 별칭도 함께 부여됩니다.

<div id="custom-aliases">
  ## 사용자 정의 별칭
</div>

특정 아티팩트 버전에 대해 사용 사례에 맞는 사용자 정의 별칭을 하나 이상 생성합니다. 예를 들어:

* `dataset_version_v0`, `dataset_version_v1`, `dataset_version_v2`와 같은 별칭을 사용하여 모델이 어떤 데이터셋으로 학습되었는지 식별할 수 있습니다.
* `best_model` 별칭을 사용하여 가장 성능이 좋은 아티팩트 모델 버전을 추적할 수 있습니다.

레지스트리에서 [**Member** 또는 **Admin** 레지스트리 역할](/ko/models/registry/configure_registry/#registry-roles)을 가진 사용자는 해당 레지스트리의 연결된 아티팩트에 사용자 정의 별칭을 추가하거나 제거할 수 있습니다. [**Restricted Viewer** 또는 **Viewer** 역할](/ko/models/registry/configure_registry/#registry-roles)을 가진 사용자는 별칭을 추가하거나 제거할 수 없습니다.

<Note>
  [보호된 별칭](/ko/models/registry/aliases/#protected-aliases)을 사용하면 수정 또는 삭제로부터 보호할 아티팩트 버전을 레이블링하고 식별할 수 있습니다.
</Note>

W&amp;B Registry 또는 Python SDK를 사용하여 사용자 정의 별칭을 생성할 수 있습니다. 사용 사례에 따라 아래에서 가장 적합한 탭을 클릭하세요.

<Tabs>
  <Tab title="W&B Registry">
    1. W&amp;B Registry로 이동합니다.
    2. 컬렉션에서 **View details** 버튼을 클릭합니다.
    3. **Versions** 섹션에서 특정 아티팩트 버전의 **View** 버튼을 클릭합니다.
    4. **Aliases** 필드 옆의 **+** 버튼을 클릭하여 별칭을 하나 이상 추가합니다.
  </Tab>

  <Tab title="Python SDK">
    Python SDK를 사용하여 아티팩트 버전을 컬렉션에 연결할 때, [`link_artifact()`](/ko/models/ref/python/experiments/run.md/#link_artifact)의 `alias` 매개변수에 별칭 목록을 선택적으로 전달할 수 있습니다. 제공한 별칭이 존재하지 않는 경우 W&amp;B가 자동으로 별칭([보호되지 않은 별칭](#custom-aliases))을 생성합니다.

    다음 코드 스니펫은 Python SDK를 사용하여 아티팩트 버전을 컬렉션에 연결하고 해당 아티팩트 버전에 별칭을 추가하는 방법을 보여줍니다. `<>` 안의 값을 실제 값으로 바꾸세요:

    ```python
    import wandb

    # 실행 초기화
    with wandb.init(entity = "<team_entity>", project = "<project_name>") as run:

        # 아티팩트 객체 생성
        # type 매개변수는 아티팩트 객체의 타입과
        # 컬렉션 타입을 모두 지정합니다
        artifact = wandb.Artifact(name = "<name>", type = "<type>")

        # 아티팩트 객체에 파일을 추가합니다.
        # 로컬 머신의 파일 경로를 지정하세요.
        artifact.add_file(local_path = "<local_path_to_artifact>")

        # 아티팩트를 연결할 컬렉션과 레지스트리를 지정합니다
        REGISTRY_NAME = "<registry_name>"
        COLLECTION_NAME = "<collection_name>"
        target_path=f"wandb-registry-{REGISTRY_NAME}/{COLLECTION_NAME}"

        # 아티팩트 버전을 컬렉션에 연결합니다
        # 이 아티팩트 버전에 하나 이상의 별칭을 추가합니다
        run.link_artifact(
            artifact = artifact, 
            target_path = target_path, 
            aliases = ["<alias_1>", "<alias_2>"]
            )
    ```
  </Tab>
</Tabs>

<div id="protected-aliases">
  ### 보호된 별칭
</div>

[보호된 별칭](/ko/models/registry/aliases/#protected-aliases)을(를) 사용하여 수정하거나 삭제하면 안 되는 아티팩트 버전에 레이블을 지정하고 이를 식별하십시오. 예를 들어, 조직의 머신 러닝 프로덕션 파이프라인에서 사용 중인 아티팩트 버전을 표시하고 식별하기 위해 `production` 보호된 별칭을 사용하는 것이 좋습니다.

[Registry admin](/ko/models/registry/configure_registry/#registry-roles) 사용자와 **Admin** 역할을 가진 [service accounts](/ko/models/support/service_account_useful/)는 보호된 별칭을 생성하고, 아티팩트 버전에 보호된 별칭을 추가하거나 제거할 수 있습니다. **Member**, **Viewer**, **Restricted Viewer** 역할을 가진 사용자와 service account는 보호된 버전의 연결을 해제하거나, 보호된 별칭이 포함된 컬렉션을 삭제할 수 없습니다. 자세한 내용은 [레지스트리 액세스 구성](/ko/models/registry/configure_registry/)을 참조하십시오.

일반적인 보호된 별칭은 다음과 같습니다:

* **Production**: 아티팩트 버전이 프로덕션 환경에서 사용할 준비가 된 상태입니다.
* **Staging**: 아티팩트 버전이 테스트에 사용할 준비가 된 상태입니다.

<div id="create-a-protected-alias">
  #### 보호된 별칭 생성
</div>

다음 단계에서는 W&amp;B Registry UI에서 보호된 별칭을 생성하는 방법을 설명합니다:

1. W&amp;B Registry로 이동합니다.
2. 레지스트리를 선택합니다.
3. 페이지 오른쪽 상단의 톱니바퀴 버튼을 클릭하여 레지스트리 설정을 엽니다.
4. **Protected Aliases** 섹션에서 **+** 버튼을 클릭해 하나 이상의 보호된 별칭을 추가합니다.

생성 후, 각 보호된 별칭은 **Protected Aliases** 섹션에서 자물쇠 아이콘이 있는 회색 직사각형으로 표시됩니다.

<Note>
  보호되지 않은 사용자 지정 별칭과는 달리, 보호된 별칭을 생성하는 기능은 Python SDK를 사용하는 프로그래밍 방식이 아니라 W&amp;B Registry UI에서만 사용할 수 있습니다. 아티팩트 버전에 보호된 별칭을 추가하려면 W&amp;B Registry UI 또는 Python SDK를 사용할 수 있습니다.
</Note>

다음 단계에서는 W&amp;B Registry UI를 사용해 아티팩트 버전에 보호된 별칭을 추가하는 방법을 설명합니다:

1. W&amp;B Registry로 이동합니다.
2. 컬렉션에서 **View details** 버튼을 클릭합니다.
3. **Versions** 섹션에서 특정 아티팩트 버전에 대해 **View** 버튼을 클릭합니다.
4. **Aliases** 필드 옆의 **+** 버튼을 클릭해 하나 이상의 보호된 별칭을 추가합니다.

보호된 별칭이 생성된 후에는 관리자가 Python SDK를 사용해 프로그래밍 방식으로 해당 별칭을 아티팩트 버전에 추가할 수 있습니다. 아티팩트 버전에 보호된 별칭을 추가하는 방법에 대한 예시는 위의 [Create a custom alias](#custom-aliases) 섹션에서 W&amp;B Registry 및 Python SDK 탭을 참고하십시오.

<div id="find-existing-aliases">
  ## 기존 별칭 찾기
</div>

[W&amp;B Registry의 전역 검색창](/ko/models/registry/search_registry/#search-for-registry-items)을 사용하여 기존 별칭을 찾을 수 있습니다. 보호된 별칭을 찾으려면 다음을 수행합니다:

1. W&amp;B Registry로 이동합니다.
2. 페이지 상단의 검색창에 검색어를 입력합니다. Enter를 눌러 검색합니다.

지정한 검색어가 기존 레지스트리 항목, 컬렉션 이름, 아티팩트 버전 태그, 컬렉션 태그 또는 별칭과 일치하는 경우, 검색 결과가 검색창 아래에 표시됩니다.

<div id="example">
  ## 예시
</div>

<Note>
  다음 코드는 이 [W&amp;B Registry Tutorial 노트북](https://colab.research.google.com/github/wandb/examples/blob/master/colabs/wandb_registry/zoo_wandb.ipynb)의 후속 예시입니다. 아래 코드를 사용하려면 먼저 [노트북에서 설명한 대로 Zoo 데이터셋을 가져와 처리](https://colab.research.google.com/github/wandb/examples/blob/master/colabs/wandb_registry/zoo_wandb.ipynb#scrollTo=87fecd29-8146-41e2-86fb-0bb4e3e3350a)해야 합니다. Zoo 데이터셋이 준비되면 아티팩트 버전을 생성하고 사용자 지정 별칭을 추가할 수 있습니다.
</Note>

다음 코드 스니펫은 아티팩트 버전을 생성하고 사용자 지정 별칭을 추가하는 방법을 보여줍니다. 이 예시는 [UCI Machine Learning Repository](https://archive.ics.uci.edu/dataset/111/zoo)의 Zoo 데이터셋과 `Zoo_Classifier_Models` 레지스트리의 `Model` 컬렉션을 사용합니다.

```python
import wandb

# 실행 초기화
with wandb.init(entity = "smle-reg-team-2", project = "zoo_experiment") as run:

    # 아티팩트 객체 생성
    # type 파라미터는 아티팩트 객체의 유형과
    # 컬렉션 유형을 모두 지정합니다
    artifact = wandb.Artifact(name = "zoo_dataset", type = "dataset")

    # 아티팩트 객체에 파일을 추가합니다.
    # 로컬 머신의 파일 경로를 지정하세요.
    artifact.add_file(local_path="zoo_dataset.pt", name="zoo_dataset")
    artifact.add_file(local_path="zoo_labels.pt", name="zoo_labels")

    # 아티팩트를 연결할 컬렉션과 레지스트리를 지정합니다
    REGISTRY_NAME = "Model"
    COLLECTION_NAME = "Zoo_Classifier_Models"
    target_path=f"wandb-registry-{REGISTRY_NAME}/{COLLECTION_NAME}"

    # 아티팩트 버전을 컬렉션에 연결합니다
    # 이 아티팩트 버전에 별칭을 하나 이상 추가합니다
    run.link_artifact(
        artifact = artifact,
        target_path = target_path,
        aliases = ["production-us", "production-eu"]
        )
```

1. 먼저 아티팩트 객체(`wandb.Artifact()`)를 생성합니다.
2. 다음으로 `wandb.Artifact.add_file()`을 사용해 데이터셋용 PyTorch 텐서 두 개를 아티팩트 객체에 추가합니다.
3. 마지막으로 `link_artifact()`로 아티팩트 버전을 `Zoo_Classifier_Models` 레지스트리의 `Model` 컬렉션에 연결합니다. 또한 `aliases` 매개변수에 `production-us`와 `production-eu` 값을 전달하여 아티팩트 버전에 두 개의 사용자 정의 별칭을 추가합니다.
