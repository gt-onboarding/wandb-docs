title: Sweep 관리
---

[W&amp;B CLI](/ko/models/ref/cli/wandb-sweep)를 사용하여 sweep을 일시 중지, 재개 및 취소할 수 있습니다. CLI의 `sweep` 명령은 `--pause`, `--resume`과 같은 플래그를 사용하여 sweep이 새로운 W&amp;B 실행을 생성하는지를 제어하며, 기존 실행에는 서로 다른 영향을 미칩니다:

* `--pause`: sweep을 일시 중지하면 에이전트는 sweep을 재개할 때까지 새로운 실행을 생성하지 않습니다. 기존 실행은 정상적으로 계속 실행됩니다.
* `--resume`: sweep을 재개하면 에이전트는 탐색 전략에 따라 새로운 실행을 계속 생성합니다.
* `--stop`: sweep을 중지하면 에이전트는 새로운 실행 생성을 중단합니다. 기존 실행은 완료될 때까지 계속됩니다.
* `--cancel`: sweep을 취소하면 에이전트는 현재 실행 중인 모든 실행을 즉시 종료하고 새로운 실행 생성을 중단합니다.

다음 지침을 따라 sweep을 일시 중지, 재개 및 취소하십시오. 각 경우에 sweep을 초기화할 때 생성된 sweep ID를 제공해야 합니다.

<div id="pause-a-sweep">
  ### 스윕 일시 중지
</div>

스윕을 일시 중지하면 새 실행의 생성을 일시적으로 중단합니다. 이미 실행 중인 실행은 완료될 때까지 계속 실행됩니다. [`wandb sweep --pause`](/ko/models/ref/cli/wandb-sweep) 명령을 사용하여 스윕을 일시 중지하십시오. 일시 중지하려는 스윕 ID를 지정하십시오.

```bash
wandb sweep --pause entity/project/sweep_ID
```

<div id="resume-a-sweep">
  ### 일시 중지된 sweep 다시 시작하기
</div>

[`wandb sweep --resume`](/ko/models/ref/cli/wandb-sweep) 명령어로 일시 중지된 sweep을 다시 시작합니다. sweep은 검색 전략에 따라 새로운 실행을 다시 생성하기 시작합니다. 다시 시작하려는 sweep ID를 지정하십시오:

```bash
wandb sweep --resume entity/project/sweep_ID
```

<div id="stop-a-sweep">
  ### 스위프 중지하기
</div>

새 실행 생성을 중단하면서 현재 실행 중인 실행은 정상적으로 완료되도록 하려면 스위프를 종료하세요. [`wandb sweep --stop`](/ko/models/ref/cli/wandb-sweep) 명령을 사용하세요:

```bash
wandb sweep --stop entity/project/sweep_ID
```

<Warning>
  프로젝트를 삭제해도 W&amp;B는 활성 상태인 [sweeps](/ko/models/sweeps) 또는 에이전트를 종료하지 않습니다.
</Warning>

<div id="cancel-a-sweep">
  ### 스위프 취소
</div>

스위프를 취소하면 현재 실행 중인 모든 실행을 즉시 중지하고 새로운 실행이 생성되지 않도록 합니다. 이는 기존 실행을 강제로 종료하는 유일한 스위프 명령입니다. [`wandb sweep --cancel`](/ko/models/ref/cli/wandb-sweep) 명령을 사용해 스위프를 취소하십시오. 취소하려는 스위프 ID를 지정하십시오.

```bash
wandb sweep --cancel entity/project/sweep_ID
```

전체 CLI 명령어 옵션 목록은 [wandb sweep](/ko/models/ref/cli/wandb-sweep) CLI 참조 가이드를 참고하세요.

<Warning>
  프로젝트를 삭제해도 W&amp;B는 활성 [sweeps](/ko/models/sweeps) 또는 에이전트를 자동으로 종료하지 않습니다.
</Warning>

<div id="understanding-sweep-and-run-statuses">
  ## 스위프 및 실행 상태 이해하기
</div>

스위프는 여러 실행을 오케스트레이션하여 다양한 하이퍼파라미터 조합을 탐색합니다. 스위프 상태와 실행 상태의 상호 작용을 이해하는 것은 하이퍼파라미터 최적화를 효과적으로 관리하는 데 필수적입니다.

<div id="key-differences">
  ### 주요 차이점
</div>

* **Sweep 상태**는 새 실행을 생성할지 여부를 제어합니다 (Running, Paused, Stopped, Cancelled, Finished, Failed, Crashed)
* **실행 상태**는 개별 실행의 수행 상태를 나타냅니다 (Pending, Running, Finished, Failed, Crashed, Killed)

<div id="stop-an-individual-run">
  ### 개별 실행 중지하기
</div>

스윕에서 [실행을 중지](/ko/models/runs/stop-runs)하면 스윕 에이전트가 자동으로 스윕의 다음 실행을 시작합니다. 이를 통해 스윕 전체 진행을 방해하지 않고 성능이 떨어지는 설정을 건너뛸 수 있습니다.

<div id="best-practices">
  ### 모범 사례
</div>

* 실행 중인 실험을 잃지 않고 탐색을 일시 중단하려면 취소 대신 `--pause`를 사용하세요
* 개별 실행 상태를 모니터링하여 체계적인 실패를 식별하세요
* 만족스러운 하이퍼파라미터를 찾았을 때는 실행을 정상적으로 종료하기 위해 `--stop`을 사용하세요
* 실행이 과도한 리소스를 사용하거나 오류를 발생시키는 긴급한 상황에서는 `--cancel`을 사용하세요
