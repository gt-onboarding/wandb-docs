  <Accordion title="내 아티팩트에는 누가 접근할 수 있나요?">
    아티팩트는 상위 프로젝트의 접근 권한을 그대로 따릅니다:

    * 비공개 프로젝트에서는 팀 구성원만 아티팩트에 접근할 수 있습니다.
    * 공개 프로젝트에서는 모든 사용자가 아티팩트를 읽을 수 있고, 팀 구성원만 생성하거나 수정할 수 있습니다.
    * 오픈 프로젝트에서는 모든 사용자가 아티팩트를 읽고 쓸 수 있습니다.

    ## 아티팩트 워크플로우

    이 섹션에서는 아티팩트를 관리하고 편집하기 위한 워크플로를 설명합니다. 많은 워크플로는 [W&amp;B API](/ko/models/track/public-api-guide)를 활용하며, 이는 W&amp;B에 저장된 데이터에 접근할 수 있게 해 주는 [클라이언트 라이브러리](/ko/models/ref/python/)의 구성 요소입니다.
  </Accordion>

  <Accordion title="Plotly 또는 Bokeh 차트를 Tables에 어떻게 추가하나요?">
    Plotly 또는 Bokeh figure를 테이블에 직접 넣는 것은 지원되지 않습니다. 대신, figure를 HTML로 내보낸 후 해당 HTML을 테이블에 포함하세요. 아래 예시는 인터랙티브 Plotly 및 Bokeh 차트를 사용하여 이를 구현하는 방법을 보여줍니다.

    <Tabs>
      <Tab title="Plotly 사용하기">
        ```python
        import wandb
        import plotly.express as px

        # Initialize a new run
        # 새로운 실행을 초기화합니다.
        with wandb.init(project="log-plotly-fig-tables", name="plotly_html") as run:

            # Create a table
            # 테이블을 생성합니다.
            table = wandb.Table(columns=["plotly_figure"])

            # Define path for Plotly figure
            # Plotly figure의 경로를 정의합니다.
            path_to_plotly_html = "./plotly_figure.html"

            # Create a Plotly figure
            # Plotly figure를 생성합니다.
            fig = px.scatter(x=[0, 1, 2, 3, 4], y=[0, 1, 4, 9, 16])

            # Export Plotly figure to HTML
            # Plotly figure를 HTML로 내보냅니다.
            # Setting auto_play to False prevents animated Plotly charts from playing automatically
            # auto_play를 False로 설정하면 애니메이션 Plotly 차트가 자동 재생되지 않습니다.
            fig.write_html(path_to_plotly_html, auto_play=False)

            # Add Plotly figure as HTML file to the table
            # Plotly figure를 HTML 파일로 테이블에 추가합니다.
            table.add_data(wandb.Html(path_to_plotly_html))

            # Log Table
            # 테이블을 로그로 기록합니다.
            run.log({"test_table": table})

        ```
      </Tab>

      <Tab title="Bokeh 사용하기">
        ```python
        from scipy.signal import spectrogram
        import holoviews as hv
        import panel as pn
        from scipy.io import wavfile
        import numpy as np
        from bokeh.resources import INLINE

        hv.extension("bokeh", logo=False)
        import wandb

        def save_audio_with_bokeh_plot_to_html(audio_path, html_file_name):
            sr, wav_data = wavfile.read(audio_path)
            duration = len(wav_data) / sr
            f, t, sxx = spectrogram(wav_data, sr)
            spec_gram = hv.Image((t, f, np.log10(sxx)), ["Time (s)", "Frequency (Hz)"]).opts(
                width=500, height=150, labelled=[]
            )
            audio = pn.pane.Audio(wav_data, sample_rate=sr, name="Audio", throttle=500)
            slider = pn.widgets.FloatSlider(end=duration, visible=False)
            line = hv.VLine(0).opts(color="white")
            slider.jslink(audio, value="time", bidirectional=True)
            slider.jslink(line, value="glyph.location")
            combined = pn.Row(audio, spec_gram * line, slider).save(html_file_name)

        html_file_name = "audio_with_plot.html"
        audio_path = "hello.wav"
        save_audio_with_bokeh_plot_to_html(audio_path, html_file_name)

        wandb_html = wandb.Html(html_file_name)
        with wandb.init(project="audio_test") as run:
            my_table = wandb.Table(columns=["audio_with_plot"], data=[[wandb_html], [wandb_html]])
            run.log({"audio_table": my_table})
        ```
      </Tab>

<Update tags={["Artifacts", "Storage"]}>
  <Accordion title="각 아티팩트 버전은 얼마나 많은 스토리지를 사용하나요?">
    두 아티팩트 버전 사이에서 변경된 파일만 스토리지 비용이 발생합니다.

    <Frame>
      <img src="/images/artifacts/artifacts-dedupe.PNG" alt="아티팩트 중복 제거" />
    </Frame>

    `cat.png`와 `dog.png` 두 개의 이미지 파일을 포함하는 `animals`라는 이름의 이미지 아티팩트를 가정해 보겠습니다:

    ```
    images
    |-- cat.png (2MB) # `v0`에서 추가됨
    |-- dog.png (1MB) # `v0`에서 추가됨
    ```

    이 아티팩트의 버전은 `v0`입니다.

    새 이미지 `rat.png`를 추가하면, 다음과 같은 내용을 가진 새 아티팩트 버전 `v1`이 생성됩니다:

    ```
    images
    |-- cat.png (2MB) # `v0`에서 추가됨
    |-- dog.png (1MB) # `v0`에서 추가됨
    |-- rat.png (3MB) # `v1`에서 추가됨
    ```

    버전 `v1`은 총 6MB를 추적하지만, 나머지 3MB를 `v0`와 공유하므로 실제로는 3MB의 공간만 차지합니다. `v1`을 삭제하면 `rat.png`에 해당하는 3MB 스토리지가 회수됩니다. `v0`을 삭제하면 `cat.png`와 `dog.png`의 스토리지 비용이 `v1`으로 이전되어, `v1`의 스토리지 크기가 6MB로 증가합니다.
  </Accordion>
</Update>

  <Accordion title="여러 아키텍처와 실행에서 아티팩트를 사용하는 방법은?">
    모델을 버전 관리하는 방법은 여러 가지가 있습니다. 아티팩트는 특정 요구사항에 맞춘 모델 버전 관리 도구를 제공합니다. 여러 모델 아키텍처를 탐색하는 프로젝트에서 자주 사용하는 방법은 아키텍처별로 아티팩트를 분리하는 것입니다. 다음 단계를 고려해 보세요:

    1. 서로 다른 각 모델 아키텍처마다 새로운 아티팩트를 생성하세요. 아티팩트의 `metadata` 속성을 사용해 아키텍처를 자세히 설명하세요. 이는 실행에 `config`를 사용하는 것과 유사합니다.
    2. 각 모델에 대해 `log_artifact`로 주기적으로 체크포인트를 로깅하세요. W&amp;B는 이러한 체크포인트의 이력을 구축하고, 가장 최근 체크포인트에 `latest` 별칭을 붙입니다. `architecture-name:latest`를 사용해 어떤 모델 아키텍처에 대해서든 최신 체크포인트를 참조할 수 있습니다.
  </Accordion>
</Update>

<Update tags={["Sweeps"]}>
  <Accordion title="Sweeps에서 사용자 정의 CLI 명령을 사용하려면 어떻게 해야 하나요?">
    학습 설정이 명령줄 인자를 전달하도록 되어 있다면, 사용자 정의 CLI 명령과 함께 W&amp;B Sweeps를 사용할 수 있습니다.

    아래 예제의 코드 스니펫은 bash 터미널에서 사용자가 `train.py`라는 이름의 Python 스크립트를 실행하면서, 스크립트가 파싱할 값들을 전달하는 모습을 보여 줍니다:

    ```bash
    /usr/bin/env python train.py -b \
        your-training-config \
        --batchsize 8 \
        --lr 0.00001
    ```

    사용자 정의 명령을 구현하려면 YAML 파일의 `command` 키를 수정하세요. 이전 예제를 기준으로 하면 설정은 다음과 같습니다:

    ```yaml
    program:
      train.py
    method: grid
    parameters:
      batch_size:
        value: 8
      lr:
        value: 0.0001
    command:
      - ${env}
      - python
      - ${program}
      - "-b"
      - your-training-config
      - ${args}
    ```

    `${args}` 키는 sweep 설정의 모든 파라미터를 `argparse`에 맞는 형식인 `--param1 value1 --param2 value2`로 확장합니다.

    `argparse`로 처리되지 않는 추가 인자를 사용하려면 다음과 같이 구현하세요:

    ```python
    parser = argparse.ArgumentParser()
    args, unknown = parser.parse_known_args()
    ```

    <Note>
      환경에 따라 `python`이 Python 2를 가리킬 수 있습니다. Python 3를 사용하려면 명령 설정에서 `python3`를 지정하세요:

      ```yaml
      program:
        script.py
      command:
        - ${env}
        - python3
        - ${program}
        - ${args}
      ```
    </Note>
  </Accordion>
</Update>

  <Accordion title="네트워크 문제를 어떻게 처리해야 하나요?">
    `wandb: Network error (ConnectionError), entering retry loop`와 같은 SSL 또는 네트워크 오류가 발생하면, 다음 해결책을 적용하세요:

    1. SSL 인증서를 갱신합니다. Ubuntu 서버에서는 `update-ca-certificates`를 실행하세요. 유효한 SSL 인증서는 보안 위험을 줄이면서 학습 로그를 동기화하는 데 필수적입니다.
    2. 네트워크 연결이 불안정하다면, [optional environment variable](/ko/models/track/environment-variables#optional-environment-variables) `WANDB_MODE`를 `offline`으로 설정해 오프라인 모드로 실행한 뒤, 이후 인터넷에 연결된 장치에서 파일을 동기화하세요.
    3. 로컬에서 실행되며 클라우드 서버로의 동기화를 피할 수 있는 [W&amp;B Private Hosting](/ko/platform/hosting/) 사용을 고려하세요.

    `SSL CERTIFICATE_VERIFY_FAILED` 오류의 경우, 회사 방화벽에서 비롯된 문제일 수 있습니다. 로컬 CA를 설정한 뒤 다음을 실행하세요:

    `export REQUESTS_CA_BUNDLE=/etc/ssl/certs/ca-certificates.crt`
  </Accordion>
</Update>

  <Accordion title="`.log()`와 `.summary`의 차이는 무엇인가요?">
    요약값은 테이블에 표시되며, 로그는 추후 플로팅을 위해 모든 값을 저장합니다.

    예를 들어, 정확도가 변경될 때마다 `run.log()`를 호출합니다. 기본적으로 `run.log()`는 해당 메트릭에 대해 요약값을 수동으로 설정하지 않은 경우 요약값을 업데이트합니다.

    산점도와 평행좌표 플롯은 요약값을 사용하고, 선 플롯은 `run.log`로 기록된 모든 값을 표시합니다.

    일부 사용자는 가장 최근에 기록된 정확도 대신 최적의 정확도를 반영하도록 요약값을 수동으로 설정하기를 선호합니다.
  </Accordion>
</Update>

    * `disabled`: 클라이언트가 모의 객체를 반환해 동작을 시뮬레이션하고, 모든 네트워크 통신을 차단합니다. 모든 로깅은 비활성화되지만, 모든 API 메서드 스텁은 계속 호출할 수 있습니다. 이 모드는 일반적으로 테스트에 사용됩니다.

<Update tags={["Tensorboard"]}>
  <Accordion title="W&B는 TensorBoard와 어떻게 다른가요?">
    W&amp;B는 TensorBoard와 통합되어 실험 추적 도구를 한층 개선합니다. W&amp;B의 설립자들은 TensorBoard 사용자들이 겪는 일반적인 불편을 해결하기 위해 W&amp;B를 만들었습니다. 주요 개선 사항은 다음과 같습니다:

    1. **모델 재현성**: W&amp;B는 실험, 탐색, 모델 재현을 쉽게 해 줍니다. 지표, 하이퍼파라미터, 코드 버전, 모델 체크포인트를 모두 기록하여 재현성을 보장합니다.

    2. **자동 정리**: W&amp;B는 시도한 모든 모델에 대한 개요를 제공하여 프로젝트 인수인계나 휴가 중에도 전체 상황을 쉽게 파악할 수 있게 합니다. 이를 통해 이전 실험을 다시 실행하느라 시간을 낭비하지 않도록 해 줍니다.

    3. **빠른 통합**: W&amp;B를 프로젝트에 5분 안에 통합할 수 있습니다. 무료 오픈소스 Python 패키지를 설치하고 몇 줄의 코드만 추가하세요. 로깅된 지표와 기록은 각 모델 실행과 함께 표시됩니다.

    4. **중앙화된 대시보드**: 학습 위치와 상관없이—로컬, 연구실 클러스터, 클라우드 스팟 인스턴스 등—일관된 대시보드에 접근할 수 있습니다. 서로 다른 머신 간에 TensorBoard 파일을 직접 관리할 필요가 없습니다.

    5. **강력한 필터링 테이블**: 다양한 모델의 결과를 검색, 필터, 정렬, 그룹화하여 효율적으로 살펴볼 수 있습니다. TensorBoard가 대규모 프로젝트에서 종종 어려움을 겪는, 서로 다른 작업에 대해 최상의 성능을 내는 모델을 쉽게 식별할 수 있습니다.

    6. **협업 도구**: W&amp;B는 복잡한 머신러닝 프로젝트에서의 협업을 강화합니다. 프로젝트 링크를 공유하고 비공개 팀을 활용해 결과를 공유하세요. 작업 로그나 발표 자료용으로 인터랙티브한 시각화와 마크다운 설명이 포함된 리포트를 만들 수 있습니다.

    ```python

    from typing import Optional

    def call_inference_with_retry(
        client, 
        messages, 
        model: str,
        max_retries: int = 3,
        base_delay: float = 1.0
    ) -> Optional[str]:
        for attempt in range(max_retries):
            try:
                response = client.chat.completions.create(

                )
                return response.choices[0].message.content
    ```

  <Accordion title="하나의 스크립트에서 여러 실행을 시작하려면 어떻게 해야 하나요?">
    단일 스크립트 내에서 여러 실행을 기록하려면 새 실행을 시작하기 전에 이전 실행을 완료해야 합니다.

    권장되는 방법은 `wandb.init()`를 컨텍스트 매니저로 사용하는 것입니다. 이렇게 하면 스크립트에서 예외가 발생할 경우 실행을 종료하고 실패한 것으로 표시합니다:

    ```python
    import wandb

    for x in range(10):
        with wandb.init() as run:
            for y in range(100):
                run.log({"metric": x + y})
    ```

    또는 `run.finish()`를 명시적으로 호출할 수도 있습니다:

    ```python
    import wandb

    for x in range(10):
        run = wandb.init()

        try:
            for y in range(100):
                run.log({"metric": x + y})

        except Exception:
            run.finish(exit_code=1)
            raise

        finally:
            run.finish()
    ```

    ## 여러 개의 활성 실행

    wandb 0.19.10부터 `reinit` 설정을 `"create_new"`로 지정하여 동시에 활성인 여러 실행을 만들 수 있습니다.

    ```python
    import wandb

    with wandb.init(reinit="create_new") as tracking_run:
        for x in range(10):
            with wandb.init(reinit="create_new") as run:
                for y in range(100):
                    run.log({"x_plus_y": x + y})

                tracking_run.log({"x": x})
    ```

    `reinit="create_new"`에 대한 자세한 내용과 W&amp;B 통합 관련 주의 사항은
    [프로세스당 여러 실행](/ko/models/runs/initialize-run)을 참고하세요.
  </Accordion>
</Update>

    W&amp;B의 메트릭 이름은 UI에서 올바르게 정렬 및 필터링할 수 있도록 GraphQL 명명 규칙을 따라야 합니다.

    ## 유효한 메트릭 이름

    * **허용되는 문자**: 알파벳(A-Z, a-z), 숫자(0-9), 밑줄(&#95;)
    * **시작 문자**: 이름은 문자 또는 밑줄로 시작해야 합니다.
    * **패턴**: 메트릭 이름은 `/^[_a-zA-Z][_a-zA-Z0-9]*$/` 패턴과 일치해야 합니다.

    ```python
    with wandb.init() as run:

      run.log({"modelAccuracy": 0.95, "learning_rate": 0.001})
    ```

    **유효하지 않은 메트릭 이름(다음은 피하십시오):**

    ```python
    with wandb.init() as run:
      run.log({"acc,val": 0.9})  # 콤마를 포함함
      run.log({"loss-train": 0.1})  # 하이픈을 포함함
      run.log({"test acc": 0.95})  # 공백을 포함함
      run.log({"5_fold_cv": 0.8})  # 숫자로 시작함
    ```

    유효하지 않은 문자를 밑줄과 같은 유효한 문자로 변경하십시오:

    * `"test acc"` 대신 `"test_acc"` 사용
    * `"loss-train"` 대신 `"loss_train"` 사용
    * `"acc,val"` 대신 `"acc_val"` 사용

        ```python
        with wandb.init(config=config_defaults) as run:
            # 여기에 학습 코드를 추가하세요
            ...
        ```
      </Tab>

        ```python
        # 하이퍼파라미터 기본값 설정
        config_defaults = {"lr": 0.1, "batch_size": 256}

        # 실행 시작
        with wandb.init() as run:
            # sweep에서 설정하지 않은 값만 업데이트
            run.config.setdefaults(config_defaults)

            # 여기에 학습 코드를 추가하세요
        ```

  <Accordion title="실행을 로깅할 때 발생하는 권한 오류를 어떻게 해결하나요?">
    W&amp;B 엔터티에 실행을 로깅할 때 발생하는 권한 오류를 해결하려면 다음 단계를 따르세요:

    * **엔터티 및 프로젝트 이름 확인**: 코드에서 W&amp;B 엔터티 및 프로젝트 이름의 철자와 대소문자가 정확한지 확인합니다.
    * **권한 확인**: 관리자에게 필요한 권한이 부여되었는지 확인합니다.
    * **로그인 자격 증명 확인**: 올바른 W&amp;B 계정으로 로그인되어 있는지 확인합니다. 다음 코드를 사용해 실행을 생성해 테스트합니다:
      ```python
      import wandb

      run = wandb.init(entity="your_entity", project="your_project")
      run.log({'example_metric': 1})
      run.finish()
      ```
    * **API key 설정**: `WANDB_API_KEY` 환경 변수를 사용합니다:
      ```bash
      export WANDB_API_KEY='your_api_key'
      ```
    * **호스트 정보 확인**: 커스텀 배포의 경우 호스트 URL을 설정합니다:
      ```bash
      wandb login --relogin --host=<host-url>
      export WANDB_BASE_URL=<host-url>
      ```
  </Accordion>
</Update>

<Update tags={["Anonymous"]}>
  <Accordion title="계정이 없는 사람은 실행 결과를 어떻게 볼 수 있나요?">
    누군가가 스크립트를 `anonymous="allow"`로 실행하면:

    1. **임시 계정 자동 생성**: W&amp;B는 로그인된 계정이 있는지 확인합니다. 없으면 익명 계정을 새로 만들고, 그 세션을 위한 API key를 저장합니다.
    2. **결과를 빠르게 로깅**: 사용자는 스크립트를 반복 실행하고 W&amp;B 대시보드에서 결과를 즉시 확인할 수 있습니다. 이러한 미인수(익명) 실행은 7일 동안 유지됩니다.
    3. **유용할 때 데이터 인수하기**: 사용자가 W&amp;B에서 가치 있는 결과를 확인하면, 페이지 상단 배너의 버튼을 클릭해 해당 실행 데이터를 실제 계정으로 저장할 수 있습니다. 인수하지 않으면 실행 데이터는 7일 후 삭제됩니다.

    <Warning>
      **익명 실행 링크는 민감합니다.** 이 링크를 가진 누구나 7일 동안 실험 결과를 조회하고 인수할 수 있으므로, 신뢰할 수 있는 사람에게만 공유하세요. 작성자의 신원을 숨긴 채 공개적으로 결과를 공유하려면, support@wandb.com으로 문의해 도움을 받으세요.
    </Warning>

    W&amp;B 사용자가 스크립트를 찾고 실행하면, 일반 실행과 마찬가지로 그 결과는 해당 사용자의 계정에 정상적으로 로깅됩니다.
  </Accordion>
</Update>

  <Accordion title="로그한 것보다 적은 데이터 포인트만 보이는 이유는 무엇인가요?">
    `Step`이 아닌 X축에 대해 메트릭을 시각화할 때는 더 적은 데이터 포인트가 보일 수 있습니다. 메트릭은 동일한 `Step`에서 로그되어야 동기화된 상태로 유지됩니다. 동일한 `Step`에서 로그된 메트릭만 샘플링되며, 샘플 간 보간 시 사용됩니다.

    **지침**

    메트릭은 하나의 `log()` 호출에 묶어서 로그하세요. 예를 들어, 다음과 같이 하는 대신:

    ```python
    import wandb
    with wandb.init() as run:
        run.log({"Precision": precision})
        ...
        run.log({"Recall": recall})
    ```

    다음과 같이 사용합니다:

    ```python
    import wandb
    with wandb.init() as run:
        run.log({"Precision": precision, "Recall": recall})
    ```

    `step` 파라미터를 수동으로 제어하려면, 다음과 같이 코드에서 메트릭을 동기화합니다:

    ```python
    with wandb.init() as run:
        step = 100  # 예시 step 값
        # Precision과 Recall을 동일한 step에서 로그
        run.log({"Precision": precision, "Recall": recall}, step=step)
    ```

    두 `log()` 호출에서 `step` 값이 동일해야 메트릭이 동일한 step으로 로그되고 함께 샘플링됩니다. `step` 값은 각 호출에서 단조 증가해야 합니다. 그렇지 않으면 `step` 값은 무시됩니다.
  </Accordion>
</Update>

  <Accordion title="서비스 계정이란 무엇이며, 왜 유용한가요?">
    **서비스 계정**은 사람 사용자가 아닌 머신 ID를 나타내며, 팀과 프로젝트 전반에 걸쳐 공통 작업을 자동화할 수 있습니다. 서비스 계정은 CI/CD 파이프라인, 자동화된 학습 작업, 기타 머신 간 워크플로에 적합합니다.

    서비스 계정의 주요 이점:

    * **라이선스 소모 없음**: 서비스 계정은 사용자 시트나 라이선스를 소모하지 않습니다.
    * **전용 API key**: 자동화된 워크플로를 위한 안전한 자격 증명을 제공합니다.
    * **사용자 귀속**: 자동화된 실행을 사람 사용자에게 선택적으로 귀속할 수 있습니다.
    * **엔터프라이즈 준비 완료**: 대규모 프로덕션 자동화를 위해 설계되었습니다.
    * **위임된 작업**: 서비스 계정은 이를 생성한 사용자 또는 조직을 대신하여 작업합니다.

    그 외에도, 서비스 계정은 주기적 재학습, 야간 빌드 등과 같이 wandb에 로깅되는 자동화된 작업을 추적하는 데 유용합니다. 원한다면, 이러한 머신이 시작한 실행 중 하나에 `WANDB_USERNAME` 또는 `WANDB_USER_EMAIL` [환경 변수](/ko/models/track/environment-variables)를 사용해 사용자 이름을 연결할 수 있습니다.

    모범 사례와 상세 설정 방법을 포함한 서비스 계정에 대한 전체 정보는 [서비스 계정을 사용해 워크플로 자동화하기](/ko/platform/hosting/iam/service-accounts)를 참조하세요. 팀 환경에서 서비스 계정이 어떻게 동작하는지에 대한 정보는 [팀 서비스 계정 동작](/ko/platform/app/settings-page/teams#team-service-account-behavior)을 참조하세요.

  <Accordion title="W&B는 멀티 테넌트에서 SSO를 지원하나요?">
    W&amp;B는 Auth0를 통해 멀티 테넌트 제공에 대해 Single Sign-On(SSO)를 지원합니다. SSO 통합은 Okta, Azure AD와 같은 모든 OIDC 규격의 IdP(Identity Provider)와 호환됩니다. OIDC 제공자를 설정하려면 다음 단계를 수행하세요:

    * IdP에서 Single Page Application(SPA)를 생성합니다.
    * `grant_type`를 `implicit` 플로우로 설정합니다.
    * callback URI를 `https://wandb.auth0.com/login/callback`으로 설정합니다.

    **W&amp;B에 필요한 정보**

    설정을 완료한 후, 해당 애플리케이션의 `Client ID`와 `Issuer URL`을 고객 성공 매니저(CSM)에게 전달하세요. W&amp;B는 이 정보를 사용해 Auth0 연결을 구성하고 SSO를 활성화합니다.
  </Accordion>

<Update tags={["Environment Variables", "Experiments"]}>
  <Accordion title="wandb.init는 제 학습 프로세스에 어떤 영향을 주나요?">
    학습 스크립트에서 `wandb.init()`이 실행되면 API 호출을 통해 서버에 실행 객체(run object)가 생성됩니다. 새로운 프로세스가 시작되어 메트릭을 스트리밍 및 수집하므로, 메인 프로세스는 정상적으로 동작할 수 있습니다. 스크립트는 로컬 파일에 기록하고, 별도 프로세스가 시스템 메트릭을 포함한 데이터를 서버로 스트리밍합니다. 스트리밍을 끄려면 학습 디렉터리에서 `wandb off`를 실행하거나 `WANDB_MODE` 환경 변수를 `offline`으로 설정하세요.
  </Accordion>
</Update>

  <Accordion title="아티팩트는 어디에 다운로드되며, 이 위치를 어떻게 제어할 수 있나요?">
    기본적으로 아티팩트는 `artifacts/` 폴더에 다운로드됩니다. 위치를 변경하려면 다음을 수행합니다:

    * [`wandb.Artifact().download`](/ko/models/ref/python/public-api/api)에 인자를 전달합니다:

      ```python
      wandb.Artifact().download(root="<path_to_download>")
      ```

    * `WANDB_ARTIFACT_DIR` [환경 변수](/ko/models/track/environment-variables)를 설정합니다:

      ```python
      import os
      os.environ["WANDB_ARTIFACT_DIR"] = "<path_to_download>"
      ```
  </Accordion>
</Update>

  <Accordion title="CSV 메트릭 내보내기에서 step이 누락되는 이유는 무엇인가요?">

    ```python
    import wandb
    import pandas as pd

    run = wandb.init()
    artifact = run.use_artifact('<entity>/<project>/<run-id>-history:v0', type='wandb-history')
    artifact_dir = artifact.download()
    df = pd.read_parquet('<path to .parquet file>')
    ```
  </Accordion>
