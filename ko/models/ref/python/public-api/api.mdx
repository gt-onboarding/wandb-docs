## <kbd>class</kbd> `Api`

W&amp;B 서버에 쿼리를 보내는 데 사용합니다.

**예제:**

```python
import wandb

wandb.Api()
```


### <kbd>메서드</kbd> `Api.__init__`

```python
__init__(
    overrides: 'dict[str, Any] | None' = None,
    timeout: 'int | None' = None,
    api_key: 'str | None' = None
) → None
```

API를 초기화합니다.

**Args:**

* `overrides`:  `base_url`을 설정할 수 있습니다.
* `using a W&B server other than `https`: //api.wandb.ai`. 또한 `entity`, `project`, `run`의 기본값을 설정할 수 있습니다.
* `timeout`:  API 요청에 대한 HTTP 타임아웃(초)입니다. 지정하지 않으면 기본 타임아웃이 사용됩니다.
* `api_key`:  인증에 사용할 API key입니다. 제공되지 않으면 현재 환경 또는 설정에 지정된 API key가 사용됩니다. 환경에 제공되거나 설정되지 않은 경우 API key 입력을 요청합니다.

### <kbd>메서드</kbd> `Api.artifact`

```python
artifact(name: 'str', type: 'str | None' = None)
```

단일 아티팩트를 반환합니다.

**Args:**

* `name`:  아티팩트의 이름. 아티팩트 이름은 파일 경로와 비슷한 형태로, 최소한 아티팩트가 로깅된 프로젝트 이름, 아티팩트 이름, 그리고 아티팩트의 버전 또는 별칭으로 구성됩니다. 선택적으로, 아티팩트를 로깅한 엔터티를 접두사로 추가하고 그 뒤에 슬래시(`/`)를 붙일 수 있습니다. 이름에 엔터티가 지정되지 않으면 실행 또는 API 설정의 엔터티가 사용됩니다.
* `type`:  가져올 아티팩트의 유형.

**Returns:**
`Artifact` 객체.

**Raises:**

* `ValueError`:  아티팩트 이름이 지정되지 않은 경우.
* `ValueError`:  아티팩트 유형이 지정되었지만 가져온 아티팩트의 유형과 일치하지 않는 경우.

**Examples:**
다음 코드 예제에서 &quot;entity&quot;, &quot;project&quot;, &quot;artifact&quot;, &quot;version&quot;, 그리고 &quot;alias&quot;는 각각 W&amp;B 엔터티, 아티팩트가 속한 프로젝트 이름, 아티팩트 이름, 그리고 아티팩트의 버전 및 별칭을 나타내는 플레이스홀더입니다.

```python
import wandb

# 프로젝트, 아티팩트 이름, 아티팩트 별칭 지정
wandb.Api().artifact(name="project/artifact:alias")

# 프로젝트, 아티팩트 이름, 특정 아티팩트 버전 지정
wandb.Api().artifact(name="project/artifact:version")

# 엔터티, 프로젝트, 아티팩트 이름, 아티팩트 별칭 지정
wandb.Api().artifact(name="entity/project/artifact:alias")

# 엔터티, 프로젝트, 아티팩트 이름, 특정 아티팩트 버전 지정
wandb.Api().artifact(name="entity/project/artifact:version")
```

**참고:**

> 이 메서드는 외부 사용만을 위한 것입니다. wandb 리포지토리 코드 내에서는 `api.artifact()`를 호출하지 마십시오.

### <kbd>메서드</kbd> `Api.artifact_collection`

```python
artifact_collection(type_name: 'str', name: 'str') → ArtifactCollection
```

지정된 타입의 단일 아티팩트 컬렉션을 반환합니다.

반환된 `ArtifactCollection` 객체를 사용하여 해당 컬렉션 내 특정 아티팩트에 대한 정보 등을 조회할 수 있습니다.

**인자(Args):**

* `type_name`:  가져올 아티팩트 컬렉션의 타입.
* `name`:  아티팩트 컬렉션 이름. 선택적으로, 아티팩트를 로깅한 엔터티를 접두사로 두고 그 뒤에 슬래시(/)를 붙여서 사용할 수 있습니다.

**반환값(Returns):**
`ArtifactCollection` 객체.

**예시(Examples):**
다음 코드 스니펫에서 &quot;type&quot;, &quot;entity&quot;, &quot;project&quot;, 그리고 &quot;artifact&#95;name&quot; 은 각각 컬렉션 타입, 사용자의 W&amp;B 엔터티, 아티팩트가 포함된 프로젝트 이름, 그리고 아티팩트 이름을 나타내는 자리표시자입니다.

```python
import wandb

collections = wandb.Api().artifact_collection(
    type_name="type", name="entity/project/artifact_name"
)

# 컬렉션에서 첫 번째 아티팩트를 가져옵니다.
artifact_example = collections.artifacts()[0]

# 아티팩트의 내용을 지정된 루트 디렉토리에 다운로드합니다.
artifact_example.download()
```

### <kbd>method</kbd> `Api.artifact_collection_exists`

```python
artifact_collection_exists(name: 'str', type: 'str') → bool
```

지정된 프로젝트와 엔터티 내에 아티팩트 컬렉션이 존재하는지 여부입니다.

**Args:**

* `name`:  아티팩트 컬렉션 이름입니다. 선택적으로, 아티팩트를 로깅한 엔터티를 접두사로 추가하고 그 뒤에 슬래시(`/`)를 붙일 수 있습니다. 엔터티 또는 프로젝트가 지정되지 않은 경우, 존재한다면 override 매개변수에서 컬렉션을 유추합니다. 그렇지 않으면 엔터티는 사용자 설정에서 가져오고, 프로젝트는 기본값인 &quot;uncategorized&quot;로 설정됩니다.
* `type`:  아티팩트 컬렉션의 유형입니다.

**Returns:**
아티팩트 컬렉션이 존재하면 True, 그렇지 않으면 False를 반환합니다.

**Examples:**
다음 코드 스니펫에서 &quot;type&quot;과 &quot;collection&#95;name&quot;은 각각 아티팩트 컬렉션의 유형과 컬렉션 이름을 의미합니다.

```python
import wandb

wandb.Api.artifact_collection_exists(type="type", name="collection_name")
```

### <kbd>method</kbd> `Api.create_automation`

```python
create_automation(
    obj: 'NewAutomation',
    fetch_existing: 'bool' = False,
    **kwargs: 'Unpack[WriteAutomationsKwargs]'
) → Automation
```

새로운 자동화를 생성합니다.

**Args:**
obj:  생성할 자동화입니다.  fetch&#95;existing:  True인 경우, 충돌하는 자동화가 이미 존재하면 에러를 발생시키는 대신 기존 자동화를 가져오려고 시도합니다.  **kwargs:  자동화를 생성하기 전에 자동화에 할당할 추가 값입니다.  제공된 경우, 자동화에 이미 설정되어 있을 수 있는 다음 키들의 값을 덮어씁니다:

* `name`: 자동화의 이름.
  * `description`: 자동화의 설명.
  * `enabled`: 자동화 활성화 여부.
  * `scope`: 자동화의 범위.
  * `event`: 자동화를 트리거하는 이벤트.
  * `action`: 자동화에 의해 트리거되는 동작.

**Returns:**
저장된 자동화.

**Examples:**
특정 프로젝트 내의 실행에서 기록한 메트릭이 사용자 지정 임계값을 초과할 때 Slack 알림을 보내는, 이름이 &quot;my-automation&quot;인 새로운 자동화를 생성합니다:

```python
import wandb
from wandb.automations import OnRunMetric, RunEvent, SendNotification

api = wandb.Api()

project = api.project("my-project", entity="my-team")

# 팀의 첫 번째 Slack 통합 사용
slack_hook = next(api.slack_integrations(entity="my-team"))

event = OnRunMetric(
     scope=project,
     filter=RunEvent.metric("custom-metric") > 10,
)
action = SendNotification.from_integration(slack_hook)

automation = api.create_automation(
     event >> action,
     name="my-automation",
     description="Send a Slack message whenever 'custom-metric' exceeds 10.",
)
```

### <kbd>메서드</kbd> `Api.create_custom_chart`

```python
create_custom_chart(
    entity: 'str',
    name: 'str',
    display_name: 'str',
    spec_type: "Literal['vega2']",
    access: "Literal['private', 'public']",
    spec: 'str | dict'
) → str
```

사용자 지정 차트 프리셋을 생성하고 해당 ID를 반환합니다.

**Args:**

* `entity`:  차트를 소유하는 엔터티(사용자 또는 팀)
* `name`:  차트 프리셋의 고유 식별자
* `display_name`:  UI에 표시되는 사람이 읽을 수 있는 이름
* `spec_type`:  사양의 유형. Vega-Lite v2 사양의 경우 반드시 &quot;vega2&quot;여야 합니다.
* `access`:  차트에 대한 접근 수준:
  * &quot;private&quot;: 차트는 이를 생성한 엔터티만 접근할 수 있음
  * &quot;public&quot;: 차트를 누구나 접근할 수 있음
* `spec`:  딕셔너리 또는 JSON 문자열 형태의 Vega/Vega-Lite 사양

**Returns:**
&quot;entity/name&quot; 형식으로 생성된 차트 프리셋의 ID

**Raises:**

* `wandb.Error`:  차트 생성에 실패한 경우
* `UnsupportedError`:  서버가 사용자 지정 차트를 지원하지 않는 경우

**Example:**

```python
    import wandb

    api = wandb.Api()

    # 간단한 막대 차트 사양 정의

         "$schema": "https://vega.github.io/schema/vega-lite/v6.json",
```

### <kbd>메서드</kbd> `Api.registries`

```python
registries(
    organization: 'str | None' = None,
    filter: 'dict[str, Any] | None' = None,
    per_page: 'int' = 100
) → Registries
```

`Registry` 객체의 지연(lazy) 이터레이터를 반환합니다.

이 이터레이터를 사용해 조직의 레지스트리 전반에서 레지스트리, 컬렉션 또는 아티팩트 버전을 검색하고 필터링할 수 있습니다.

**Args:**

* `filter`:  (dict, optional) 지연 레지스트리 이터레이터의 각 객체에 적용할 MongoDB 스타일의 필터입니다. 레지스트리에 대해 필터링할 수 있는 필드는 `name`, `description`, `created_at`, `updated_at`입니다. 컬렉션에 대해 필터링할 수 있는 필드는 `name`, `tag`, `description`, `created_at`, `updated_at`입니다. 버전에 대해 필터링할 수 있는 필드는 `tag`, `alias`, `created_at`, `updated_at`, `metadata`입니다.
* `per_page`:  쿼리 페이지네이션에 사용할 페이지 크기를 설정합니다.

**Returns:**
`Registry` 객체의 지연(lazy) 이터레이터.

**Examples:**
이름에 &quot;model&quot;이 포함된 모든 레지스트리를 찾습니다.

```python

api = wandb.Api()  # 엔터티가 여러 조직에 속한 경우 조직을 지정하세요
api.registries(filter={"name": {"$regex": "model"}})
```

레지스트리에서 이름이 &quot;my&#95;collection&quot;이고 태그가 &quot;my&#95;tag&quot;인 모든 컬렉션을 찾습니다

```python
api.registries().collections(filter={"name": "my_collection", "tag": "my_tag"})
```

컬렉션 이름에 &quot;my&#95;collection&quot;이 포함되고 버전 별칭이 &quot;best&quot;인 모든 아티팩트 버전을 레지스트리에서 찾습니다

```python
api.registries().collections(
    filter={"name": {"$regex": "my_collection"}}
).versions(filter={"alias": "best"})
```

레지스트리에서 &quot;model&quot;을 포함하고 태그가 &quot;prod&quot;이거나 별칭이 &quot;best&quot;인 모든 아티팩트 버전을 찾습니다

```python
api.registries(filter={"name": {"$regex": "model"}}).versions(
    filter={"$or": [{"tag": "prod"}, {"alias": "best"}]}
)
```

* `host`: 실행이 수행된 호스트 이름입니다.
* `jobType`: 실행의 작업 유형 또는 목적입니다.
* `name`: 실행의 고유 식별자입니다. (예: &quot;a1b2cdef&quot;)
* `state`: 실행의 현재 상태입니다.
* `tags`: 실행과 연결된 태그입니다.
* `username`: 실행을 시작한 사용자의 사용자 이름입니다.

또한 실행의 config 항목이나 summary 메트릭으로도 필터링할 수 있습니다. 예를 들어 `config.experiment_name`, `summary_metrics.loss` 등입니다.

더 복잡한 필터링을 위해서는 MongoDB 쿼리 연산자를 사용할 수 있습니다. 자세한 내용은 https://docs.mongodb.com/manual/reference/operator/query 를 참조하세요. 다음 연산들이 지원됩니다:

* `$and`
* `$or`
* `$nor`
* `$eq`
* `$ne`
* `$gt`
* `$gte`
* `$lt`
* `$lte`
* `$in`
* `$nin`
* `$exists`
* `$regex`

**Args:**

* `path`:  (str) 프로젝트에 대한 경로이며, &quot;entity/project&quot; 형식이어야 합니다.
* `filters`:  (dict) MongoDB 쿼리 언어를 사용하여 특정 실행들을 조회하는 필터입니다. config.key, summary&#95;metrics.key, state, entity, createdAt 등 실행 속성으로 필터링할 수 있습니다.
* `For example`:  `{"config.experiment_name": "foo"}` 는 experiment name이 &quot;foo&quot;로 설정된 config 항목을 가진 실행들을 찾습니다.
* `order`:  (str) 정렬 기준은 `created_at`, `heartbeat_at`, `config.*.value`, 또는 `summary_metrics.*` 가 될 수 있습니다. order 앞에 +를 붙이면 오름차순(기본값), -를 붙이면 내림차순입니다. 기본 정렬 기준은 가장 오래된 것부터 최신까지의 run.created&#95;at입니다.
* `per_page`:  (int) 쿼리 페이지네이션을 위한 페이지 크기를 설정합니다.
* `include_sweeps`:  (bool) 결과에 sweep 실행을 포함할지 여부입니다.
* `lazy`:  (bool) 더 빠른 성능을 위해 지연 로딩을 사용할지 여부입니다. True(기본값)일 때는 필수 실행 메타데이터만 초기 로딩되며, config, summaryMetrics, systemMetrics 같은 무거운 필드는 접근 시점에 필요에 따라 로딩됩니다. 전체 데이터를 미리 로딩하려면 False로 설정하세요.

**Returns:**
`Run` 객체들의 반복 가능한 컬렉션인 `Runs` 객체를 반환합니다.

**Examples:**

```python
import wandb
from wandb.apis.public import Api

# 프로젝트에서 config.experiment_name이 "foo"로 설정된 실행을 찾습니다
Api.runs(path="my_entity/project", filters={"config.experiment_name": "foo"})
```

```python
# config.experiment_name이 "foo" 또는 "bar"로 설정된 프로젝트의 실행 찾기
Api.runs(
    path="my_entity/project",
    filters={
         "$or": [
             {"config.experiment_name": "foo"},
             {"config.experiment_name": "bar"},
         ]
    },
)
```

```python
# config.experiment_name이 정규식과 일치하는 프로젝트의 실행 찾기
# (앵커는 지원되지 않음)
Api.runs(
    path="my_entity/project",
    filters={"config.experiment_name": {"$regex": "b.*"}},
)
```

```python
# 실행 이름이 정규식과 일치하는 프로젝트의 실행 찾기
# (앵커는 지원되지 않음)
Api.runs(
    path="my_entity/project", filters={"display_name": {"$regex": "^foo.*"}}
)
```

```python
# 손실값 오름차순으로 정렬된 프로젝트의 실행 찾기
Api.runs(path="my_entity/project", order="+summary_metrics.loss")
```
