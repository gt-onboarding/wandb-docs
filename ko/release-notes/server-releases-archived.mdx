<Update label="v0.63.0" description="2024년 12월 10일">
  ## 기능

  **[W&amp;B Weave](https://wandb.ai/site/weave/)가 이제 AWS Dedicated Cloud에서 일반 제공(GA)됩니다. 팀에서 신뢰할 수 있는 방식으로 생성형 AI 앱을 구축하고 프로덕션에 배포하려는 경우, 담당 W&amp;B 팀에 문의하세요.**

  <Frame>
    ![Weave UI](https://github.com/user-attachments/assets/22786cbc-7d69-4505-b329-78cb87734d19)
  </Frame>

  이번 릴리스에는 다음과 같은 추가 업데이트가 포함됩니다:

  * W&amp;B Models가 이제 ***Azure 공용 클라우드***&#xC640; 원활하게 통합됩니다. Azure 구독에서 Azure 리전 내 Dedicated Cloud 인스턴스를 직접 생성하고, 이를 Azure ISV 리소스로 관리할 수 있습니다. [이 통합은 현재 비공개 프리뷰입니다](https://wandb.ai/site/partners/azure).
  * 분산 실행에서 로그와 메트릭을 라벨(예: node)별로 구분할 수 있도록, run settings 객체에서 x&#95;label(예: node-0)을 지정하는 기능이 추가되었습니다. 이를 통해 워크스페이스에서 라벨별 시스템 메트릭과 콘솔 로그를 그룹화하여 시각화할 수 있습니다.
  * ***곧 제공 예정***: 이번 주 패치 릴리스에서, 인스턴스 내 모든 팀에 대해 W&amp;B 워크로드를 자동화할 수 있도록 조직 수준 서비스 계정을 사용할 수 있게 됩니다. 서비스 계정의 접근 범위를 더 세밀하게 제어하고자 하는 경우, 기존 팀 수준 서비스 계정 역시 계속 사용할 수 있습니다.
    * 조직 수준 서비스 계정이 Registry와 상호작용할 수 있도록 허용합니다. 이러한 서비스 계정은 초대 모달을 사용해 Registry에 초대할 수 있으며, 해당 조직 역할과 함께 멤버 테이블에 표시됩니다.

  ## 수정 사항

  * `Create Artifact` 권한이 포함된 커스텀 역할을 생성한 사용자가 프로젝트에 아티팩트를 로그할 수 없던 문제를 수정했습니다.
  * BYOB에 대해 서브패스 지원이 구성된 인스턴스에서 파일 메타데이터 로깅에 문제가 발생하던 현상을 수정했습니다.
  * 조직 Registry 자동화에서 사용 중인 경우, 웹훅 삭제를 차단하도록 변경했습니다.
</Update>

<Update label="v0.61.0" description="2024년 10월 17일">
  ## 기능

  **이 릴리스는 월간 W&amp;B 서버 메이저 릴리스와는 다른 일정으로 제공되는 소규모 기능 및 패치 릴리스입니다.**

  * 조직 관리자는 이제 조직 대시보드에서 Models 및 [W&amp;B Weave](/ko/weave/) 모두에 대해 Models 좌석 수 및 접근 제어를 일원화된 방식으로 구성할 수 있습니다. 이 변경을 통해 Dedicated Cloud 또는 Self-Managed 인스턴스에서 [Weave](/ko/weave/)가 활성화된 경우, 사용자 관리를 보다 효율적으로 수행할 수 있습니다.
    * [Weave](/ko/weave/) 요금은 사용량 기반이며, 좌석 수 기준이 아닙니다. 좌석 관리는 Models 제품에만 적용됩니다.
  * 이제 [팀 및 제한 범위 프로젝트에 대해 프로젝트 수준에서 접근 역할을 구성](https://docs.wandb.ai/platform/hosting/iam/access-management/restricted-projects/)할 수 있습니다. 이를 통해 동일한 팀 내 서로 다른 프로젝트에서 사용자에게 서로 다른 접근 역할을 부여할 수 있으며, 엔터프라이즈 거버넌스 요구사항을 충족하기 위한 강력한 제어 수단이 하나 더 추가됩니다.

  ## 수정 사항

  * 릴리스 업그레이드 과정에서 수행되는 기본 데이터베이스 스키마 변경이 플랫폼 시작 시점에 타임아웃될 수 있던 문제를 수정했습니다.
  * 기본 parquet store 서비스의 성능을 추가로 개선하여, 사용자에게 차트 로딩 시간을 더 단축했습니다. Parquet store 서비스는 Dedicated Cloud와 [W&amp;B kubernetes operator](https://docs.wandb.ai/platform/hosting/operator)를 기반으로 하는 Self-Managed 인스턴스에서만 사용할 수 있습니다.
  * 기본 parquet store 서비스에서 발생하던 높은 CPU 사용률 문제를 해결하여, 효율적인 차트 로딩 성능을 사용자에게 더 안정적으로 제공하도록 했습니다. Parquet store 서비스는 Dedicated Cloud와 [W&amp;B kubernetes operator](https://docs.wandb.ai/platform/hosting/operator)를 기반으로 하는 Self-Managed 인스턴스에서만 사용할 수 있습니다.
</Update>

<Update label="v0.60.0" description="2024년 9월 26일">
  <Note>
    릴리스 버전 관리 문제로 인해 0.60.0은 0.58.0 이후의 다음 메이저 릴리스입니다. 0.59.0은 0.58.0의 패치 릴리스 중 하나였습니다.

  ## 기능

  * 웹 콘텐츠 접근성 지침(Web Content Accessibility Guidelines, WCAG) 표준의 2.2 레벨 AA에 대한 1.1.1 컴플라이언스 최종 업데이트입니다.
  * 이제 Self-Managed 인스턴스에서 W&amp;B kubernetes operator를 사용하여 자동 버전 업그레이드를 비활성화할 수 있습니다. 이 기능이 필요하다면 담당 W&amp;B 팀에 요청할 수 있습니다.\
    W&amp;B는 각 버전에 대해 6개월 지원 종료(end-of-life) 기간을 준수하기 위해 모든 인스턴스가 주기적으로 업그레이드되도록 요구합니다. W&amp;B는 6개월보다 오래된 버전은 지원하지 않습니다.

  ## 수정 사항

  * Dedicated Cloud 및 Self-Managed 인스턴스에서 인스턴스 관리자(instance admin)가 개인 엔터티의 워크스페이스에 접근할 수 없던 버그를 수정했습니다.
  * SCIM Groups 및 Users GET 엔드포인트가 응답에서 서비스 계정을 필터링하도록 수정했습니다. 이제 해당 엔드포인트는 서비스 계정이 아닌 사용자만 반환합니다.
  * 팀 관리자가 팀에서 사용자를 삭제하면서 동시에 전체 인스턴스에서 그 사용자를 삭제할 수 있던 사용자 관리 버그를 수정했습니다. 전체 인스턴스/조직에서 사용자를 삭제하는 책임은 인스턴스 또는 Org 관리자에게 있습니다.

  ## 성능 향상

  * 많은 메트릭이 있는 워크스페이스에서 패널을 추가할 때의 지연 시간을 최대 90%까지 줄였습니다.
  * 실행이 자주 재개되는 경우, blob storage로의 parquet 내보내기 신뢰성과 성능을 개선했습니다.\
    blob storage로의 parquet 형식 실행 내보내기는 Dedicated Cloud와, W&amp;B kubernetes operator를 사용해 활성화된 Self-Managed 인스턴스에서 사용할 수 있습니다.
</Update>

<Update label="v0.58.1" description="2024년 9월 4일">
  ## 기능

  * 이제 W&amp;B는 **Secure storage connector, 즉 Bring your own bucket** 기능에서 sub-path를 지원합니다. 인스턴스 또는 팀 수준에서 bucket을 구성할 때 sub-path를 제공할 수 있습니다. 이는 신규 bucket 구성에만 적용되며, 기존에 구성된 bucket에는 적용되지 않습니다.
  * Google Cloud 및 Azure의 최신 Dedicated Cloud 인스턴스에서 W&amp;B가 관리하는 스토리지는 기본적으로 **W&amp;B가 관리하는 클라우드 네이티브 키**로 암호화됩니다. 이는 이미 AWS 인스턴스에서는 제공되고 있습니다. 각 인스턴스 스토리지는 인스턴스마다 고유한 키로 암호화됩니다. 지금까지 Google Cloud 및 Azure의 모든 인스턴스는 기본 클라우드 제공업체 관리 암호화 키에 의존했습니다.
  * run config 및 summary의 필드를 클릭 한 번으로 복사할 수 있도록 했습니다.
  * Self-Managed 인스턴스에서 W&amp;B kubernetes operator를 사용하는 경우, 이제 선택적으로 controller manager에 커스텀 CA를 사용할 수 있습니다.
  * W&amp;B kubernetes operator가 기본적으로 non-root 컨텍스트에서 실행되도록 수정하여 OpenShift의 Security Context Constraints(SCCs)에 맞추었습니다. 이 변경으로 OpenShift의 보안 정책을 준수하면서 Self-Managed 인스턴스를 더 원활하게 배포할 수 있습니다.

  ## 수정 사항

  * 워크스페이스에서 패널을 리포트로 내보낼 때 패널 검색 정규식(panel search regex)이 올바르게 적용되지 않던 문제를 수정했습니다.
  * `GORILLA_DISABLE_PERSONAL_ENTITY`를 `true`로 설정해도 사용자가 개인 엔터티에서 프로젝트를 생성하거나 기존 프로젝트에 기록하는 기능이 비활성화되지 않던 문제를 수정했습니다.

  ## 성능 향상

  * 10만 개 이상의 포인트가 로그되는 실험에 대해 성능과 안정성을 크게 개선했습니다. Self-Managed 인스턴스에서는 배포가 W&amp;B kubernetes operator로 관리되는 경우에 사용할 수 있습니다.
  * 큰 워크스페이스에서 변경 사항을 저장할 때 매우 느리거나 실패하던 문제를 수정했습니다.
  * 큰 워크스페이스에서 워크스페이스 섹션을 여는 지연 시간을 개선했습니다.
</Update>

<Update label="v0.57.2" description="2024년 7월 24일">
  ## 기능

  **이제 identity federation 기능을 사용해 JWT(JSON Web Token)를 통해 wandb SDK 또는 CLI에서 W&amp;B 인스턴스에 액세스할 수 있습니다. 이 기능은 현재 프리뷰 단계입니다.** 자세한 내용은 [Identity federation](https://docs.wandb.ai/platform/hosting/iam/identity_federation)을 참고하고, 궁금한 점이 있으면 W&amp;B 팀에 문의하세요.

  * Workspace 패널을 Reports로 내보낼 수 있는 새 `Add to reports` 드로어가 개선되었습니다.
  * 아티팩트 프로젝트 브라우저에서 아티팩트 메타데이터를 기준으로 필터링할 수 있습니다.
  * `${artifact_metadata.KEY}`를 통해 웹훅 페이로드에 아티팩트 메타데이터를 전달할 수 있습니다.
  * RunSystemMetrics 컴포넌트에 GPU 메모리 사용량 패널이 추가되어, 앱 프런트엔드에서 실행별 GPU 메트릭 시각화가 향상되었습니다.
  * 모바일 사용자는 이제 훨씬 더 부드럽고 직관적인 Workspace 경험을 누릴 수 있습니다.
  * Google Cloud 또는 Azure에서 W&amp;B Dedicated Cloud를 사용하는 경우, 이제 인스턴스에 대해 프라이빗 연결을 활성화하여 AI 워크로드와 (선택적으로) 브라우저 클라이언트의 모든 트래픽이 클라우드 제공업체의 프라이빗 네트워크만을 통해 전송되도록 보장할 수 있습니다. 자세한 내용은 [Private connectivity](https://docs.wandb.ai/platform/hosting/data-security/private-connectivity)를 참고하고, 궁금한 점이 있으면 W&amp;B 팀에 문의하세요.
  * 팀 설정 보기에서 팀 수준 서비스 계정이 새 탭에 별도로 표시됩니다. 서비스 계정은 더 이상 Members 탭에 나열되지 않습니다. 또한 API key는 이제 숨겨지며 팀 관리자만 복사할 수 있습니다.
  * Dedicated Cloud가 이제 Google Cloud의 서울 리전에서 사용 가능합니다.

  ## 수정 사항

  * 여러 플롯에서 Gaussian smoothing이 지나치게 강하게 적용되던 문제를 수정했습니다.
  * `Ignore Outliers in Chart Scaling` 버튼을 눌러도 UI Workspace에서 아무 효과가 없던 문제를 수정했습니다.
  * 비활성화된 사용자를 조직에 초대할 수 없도록 제한했습니다.
  * SCIM API를 사용해 인스턴스에 추가된 사용자가 정상적으로 온보딩할 수 없었던 문제를 수정했습니다.

  ## 성능 개선

  * 패널 설정을 편집하고 변경 사항을 적용할 때의 성능을 크게 개선했습니다.
  * 대규모 Workspace에서 실행 가시성 토글의 반응성을 개선했습니다.
  * 대규모 Workspace의 플롯에서 차트 호버 및 브러싱 성능을 개선했습니다.
  * 많은 키를 가진 Workspace의 메모리 사용량과 로딩 시간을 줄였습니다.
</Update>

  ## Features

  * W&amp;B Experiments의 새로운 Full Fidelity 선 그래프는 x축 전체의 모든 데이터를 집계하여 각 버킷 내의 최소, 최대, 평균 값을 표시함으로써 학습 지표의 가시성을 향상합니다. 이를 통해 사용자는 이상치를 쉽게 찾아내고, 다운샘플링 손실 없이 고충실도 세부 정보를 확대해서 확인할 수 있습니다.  [문서에서 더 알아보기](https://docs.wandb.ai/models/app/features/panels/line-plot/sampling).
  * 이제 Dedicated Cloud 및 Self-Managed 인스턴스에서 [팀 수준 BYOB(secure storage connector)를 위한 cross-cloud 스토리지 버킷](https://docs.wandb.ai/platform/hosting/data-security/secure-storage-connector#cross-cloud-or-s3-compatible-storage-for-team-level-byob)을 사용할 수 있습니다. 예를 들어 AWS의 W&amp;B 인스턴스에서 Azure Blob Storage 또는 Google Cloud Storage를 팀 수준 BYOB로 구성할 수 있으며, 각 cross-cloud 조합에 대해서도 동일하게 설정할 수 있습니다.
  * 같은 맥락에서 이제 Dedicated Cloud 및 Self-Managed 인스턴스에서 [MinIO와 같은 S3 호환 스토리지 버킷을 팀 수준 BYOB(secure storage connector)를 위해](https://docs.wandb.ai/platform/hosting/data-security/secure-storage-connector#cross-cloud-or-s3-compatible-storage-for-team-level-byob) 사용할 수 있습니다. 예를 들어 Google Cloud의 W&amp;B 인스턴스에서 클라우드 또는 온프레미스에 호스팅된 MinIO 버킷을 팀 수준 BYOB로 구성할 수 있습니다.

    <Frame>

  * Viewer 역할
    이제 W&amp;B Server에 Viewer 역할이 도입되어, 더 폭넓은 대상과 W&amp;B에서의 결과를 공유할 수 있습니다. 이 역할을 가진 사용자는 팀에서 만든 모든 내용을 볼 수 있지만, 생성·편집·삭제는 할 수 없습니다. 이 좌석은 기존 W&amp;B Server 좌석과 별도로 측정되므로, 업데이트된 라이선스를 요청하려면 W&amp;B 계정 담당자에게 문의하세요.
  * 공유 기능 개선: 선택적 매직 링크 및 Viewer의 간편한 가입
    팀 관리자는 이제 팀 및 팀 구성원에 대해 매직 링크 공유를 끌 수 있습니다. 팀 설정에서 공개 공유를 비활성화하면 팀 프라이버시 제어를 강화할 수 있습니다. 동시에, 리포트 링크를 받은 사용자가 가입 후 W&amp;B에서 해당 리포트에 더 쉽게 접근할 수 있도록 개선했습니다.
  * 리포트 작성 기능 개선
    <Frame>
      ![향상된 초안 게시, 편집 및 협업 기능을 갖춘 리포트 작성 인터페이스](https://github.com/wandb/server/assets/97066933/c2858fd5-d2f6-47e3-9e93-f8d048df4f59)
    </Frame>
    리포트는 ML 팀 외부의 사람들을 포함해 조직 전체에 W&amp;B에서의 결과를 공유하는 데 유용합니다. 리포트를 가능한 한 간단하고 마찰 없이 생성·공유할 수 있도록 여러 개선을 진행했습니다. 여기에는 초안 게시, 편집, 관리, 공유 UX가 향상된 리포트 초안 작성 경험이 포함되며, 이를 통해 팀이 리포트로 더 잘 협업할 수 있습니다.
  * 내비게이션 업데이트
    W&amp;B가 지원하는 ML 워크플로의 범위가 확장됨에 따라, 애플리케이션 내 이동이 어렵다는 피드백을 받았습니다. 이에 따라 내비게이션 사이드바를 업데이트하여 제품 영역에 더 명확한 레이블을 추가하고, 일부 상세 화면에 백링크를 추가했습니다. 또한 기능의 강력함을 더 잘 반영하기 위해 “Triggers” 이름을 “Automations”로 변경했습니다.
